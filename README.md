# Torrent Manager

Torrent Manager — небольшой сервис на Spring Boot, который следит за загрузками в qBittorrent и приостанавливает медленные торренты, когда достигнут заданный лимит активных загрузок. Сервис хранит состояние в локальном файле, чтобы позднее возобновлять торренты, приостановленные им самим.

## Статус проекта

Версия `0.8.0` — работоспособный выпуск до версии 1.0. Помимо управления очередью и уведомлений сервис ведёт долговременную аналитику каждого незавершённого торрента, формирует ежедневный диагностический отчёт и позволяет запросить такой отчёт вручную. До выпуска `1.0.0` конфигурация и поведение сервиса могут изменяться.

По умолчанию сервис запускается в режиме имитации (`dry-run`). Проверьте журналы и конфигурацию, прежде чем разрешать ему останавливать или возобновлять торренты.

## Требования

- Java 25 или Docker
- qBittorrent с включённым веб-интерфейсом

## Настройка

Скопируйте `.env.example` в `.env` и замените все значения-заглушки:

```dotenv
QBITTORRENT_URL=http://127.0.0.1:8080
QBITTORRENT_USERNAME=replace-me
QBITTORRENT_PASSWORD=replace-me
APP_DIR=/absolute/path/to/torrent-manager
TORRENT_MANAGER_DRY_RUN=true
TORRENT_MANAGER_RETRY_COOLDOWN=20m
TORRENT_MANAGER_FAIR_ROTATION_SLOTS=1
TRAFFIC_STATS_POLL_INTERVAL=1m
DOWNLOAD_MONITOR_POLL_INTERVAL=1m
DOWNLOAD_HISTORY_MAX_ENTRIES=1000
TORRENT_ANALYTICS_ENABLED=true
DAILY_REPORT_ENABLED=false
TZ=UTC
```

Переменная `APP_DIR` используется только в `compose.yaml` и должна указывать на каталог, содержащий `torrent-manager.jar`. Файл `.env`, журналы, рабочие данные, результаты сборки и архивы для развёртывания исключены из Git.

Дополнительные параметры описаны в `src/main/resources/application.properties`. Их можно переопределять стандартными средствами конфигурации Spring Boot.

`TORRENT_MANAGER_RETRY_COOLDOWN` задаёт минимальное время ожидания перед повторным запуском торрента, остановленного менеджером. По умолчанию используется `20m`. Поддерживаются форматы длительности Spring, например `30s`, `20m` и `2h`.

### Справедливая ротация старых загрузок

Чтобы ранее остановленные торренты не оставались в конце постоянно пополняющейся очереди, менеджер выделяет им настраиваемое число приоритетных кандидатов. После истечения cooldown выбирается торрент с самым ранним временем повторной попытки, перемещается в начало очереди qBittorrent и запускается. qBittorrent продолжает соблюдать собственный общий лимит активных загрузок — forced-start не используется.

Пока выбранный торрент активен или ожидает запуска в очереди, его ротационный слот считается занятым. После завершения либо повторной остановки слот получает следующий подходящий торрент. Значение задаётся переменной:

```dotenv
TORRENT_MANAGER_FAIR_ROTATION_SLOTS=1
```

Рекомендуемое начальное значение — `1`. Его можно увеличить, если старых частично скачанных торрентов много, либо установить `0`, чтобы вернуть прежнее поведение без приоритетной ротации. При пустой очереди менеджер, как и раньше, использует все свободные слоты для доступных повторных попыток.

`TZ` задаёт часовую зону для времени в журнале. Используйте имя из базы IANA, например `Europe/Moscow`; по умолчанию применяется `UTC`.

## Мониторинг завершения загрузок

Сервис независимо от алгоритма управления скоростью отслеживает переход каждого торрента из незавершённого состояния в завершённое. При обнаружении перехода публикуется внутреннее событие `DownloadCompletedEvent` и появляется запись в журнале:

```text
Загрузка торрента завершена: 'Название' (hash=...)
```

Письмо о завершении содержит два показателя времени: общее время от добавления в
qBittorrent, включая очередь и паузы, и накопленное активное время загрузки без
очереди. Второй показатель начинает накапливаться после запуска версии `0.8.0`;
для торрентов, уже находившихся в клиенте на момент обновления, он отражает только
наблюдавшийся сервисом период.

При первом запуске текущие торренты используются как базовый снимок, поэтому уже скачанные файлы не создают ложных событий. Состояние сохраняется в `data/download-monitor-state.properties`: если торрент завершится во время перезапуска сервиса, событие будет обнаружено при следующем опросе. Удалённые из qBittorrent торренты автоматически удаляются из снимка.

Интервал проверки задаётся переменной `DOWNLOAD_MONITOR_POLL_INTERVAL` и по умолчанию равен одной минуте. Внутреннее событие отделено от способа доставки: в следующих версиях к нему можно подключить webhook, Telegram или Trakt, не меняя сам мониторинг.

Каждое обнаруженное завершение сохраняется независимо от текущего списка qBittorrent в `data/download-completions.json`. По умолчанию хранятся последние 1000 записей; лимит задаётся переменной `DOWNLOAD_HISTORY_MAX_ENTRIES`. Новые записи получают статус доставки `NOT_CONFIGURED`, пока к событиям не подключён канал уведомлений.

Последние завершения доступны через API, новые записи возвращаются первыми:

```text
GET /api/downloads/completions?limit=50
```

Пример ответа:

```json
[
  {
    "id": "8df62af7-7746-4525-98d2-589f14cab321",
    "hash": "torrent-hash",
    "name": "Название фильма",
    "completedAt": "2026-08-19T10:15:00Z",
    "deliveryStatus": "NOT_CONFIGURED"
  }
]
```

## Уведомления по электронной почте

После завершения загрузки Torrent Manager может отправить письмо через SMTP. Отправка выполняется отдельным фоновым обработчиком и не задерживает мониторинг qBittorrent. Сначала событие сохраняется в истории со статусом `PENDING`, после успешной отправки получает статус `DELIVERED`.

При временной ошибке выполняются повторные попытки через 1 минуту, 5 минут, 30 минут и 2 часа. После пяти неудачных попыток запись получает статус `FAILED`. Количество попыток, время следующей попытки, время доставки и последняя ошибка доступны через API истории и сохраняются после перезапуска контейнера.

Для Яндекс Почты создайте отдельный пароль приложения и используйте следующие параметры:

```dotenv
EMAIL_NOTIFICATIONS_ENABLED=true
EMAIL_SMTP_HOST=smtp.yandex.ru
EMAIL_SMTP_PORT=465
EMAIL_SMTP_USERNAME=sender@yandex.ru
EMAIL_SMTP_PASSWORD=app-password
EMAIL_SMTP_SSL=true
EMAIL_SMTP_STARTTLS=false
EMAIL_TO=recipient@example.com
EMAIL_NOTIFICATION_TEST_ENDPOINT_ENABLED=false
```

Адрес отправителя всегда берётся из `EMAIL_SMTP_USERNAME`, поэтому сервис не может попытаться отправить письмо от имени другого ящика. Не добавляйте рабочий `.env` и пароль приложения в Git. Если уведомления отключены, новые записи сохраняются со статусом `NOT_CONFIGURED`.

Для проверки SMTP без ожидания завершения торрента временно задайте
`EMAIL_NOTIFICATION_TEST_ENDPOINT_ENABLED=true` и отправьте запрос:

```shell
curl -X POST http://localhost:8092/api/notifications/email/test
```

Endpoint использует только заранее настроенный `EMAIL_TO` и не принимает адрес из запроса. После проверки верните `EMAIL_NOTIFICATION_TEST_ENDPOINT_ENABLED=false`.

### Предупреждение об общей остановке загрузок

Дополнительный монитор следит за суммарной скоростью qBittorrent, не вмешиваясь в алгоритм остановки и повторного запуска торрентов. Проверка начинается только при наличии хотя бы одного незавершённого активного торрента или торрента в очереди.

По умолчанию инцидент фиксируется, если скорость не превышает `10KB/s` в течение `20m`. За это время основной менеджер продолжает штатную ротацию медленных торрентов. Если скорость не появилась, отправляется одно предупреждение. Повторные письма для того же инцидента подавляются.

Когда скорость держится не ниже `100KB/s` в течение `2m`, отправляется отдельное уведомление о восстановлении. Если активных и ожидающих загрузок больше нет, инцидент также закрывается.

```dotenv
DOWNLOAD_STALL_ALERT_ENABLED=true
DOWNLOAD_STALL_ALERT_POLL_INTERVAL=1m
DOWNLOAD_STALL_ALERT_INITIAL_DELAY=2m
DOWNLOAD_STALL_ALERT_ZERO_SPEED_THRESHOLD=10KB
DOWNLOAD_STALL_ALERT_AFTER=20m
DOWNLOAD_STALL_ALERT_RECOVERY_SPEED=100KB
DOWNLOAD_STALL_ALERT_RECOVERY_WINDOW=2m
```

Предупреждение означает подтверждённое отсутствие скорости, но не устанавливает техническую причину: это может быть зависание qBittorrent, отсутствие пиров, проблема сети или диска. Оно может быть отправлено только пока работают Torrent Manager, сеть и SMTP.

## Аналитика торрентов и ежедневный отчёт

Версия `0.8.0` сохраняет отдельное состояние каждого незавершённого торрента в
`data/torrent-analytics-state.json`. Для него учитываются текущий прогресс и скорость,
время добавления и первого наблюдения, время последнего прироста, накопленное время
активной загрузки и ожидания в очереди, продолжительность отсутствия сидов, а также
остановки, возобновления и справедливые ротации менеджера. Перезапуск контейнера не
обнуляет эти сведения; длительный простой приложения не засчитывается как активная
загрузка.

На основании этих данных выделяются торренты, требующие внимания: почти завершённые
без прогресса, долго находящиеся без сидов, зависшие в принудительном режиме,
пережившие много безрезультатных попыток и давно добавленные загрузки с низким
прогрессом. Указанная причина является диагностической оценкой по наблюдаемым
признакам, а не гарантированным диагнозом qBittorrent, сети или диска.

Чтобы ежедневно в 09:00 по локальному времени контейнера получать письмо, включите
email-уведомления и отчёт:

```dotenv
TZ=Europe/Moscow
EMAIL_NOTIFICATIONS_ENABLED=true
DAILY_REPORT_ENABLED=true
DAILY_REPORT_TIME=09:00
```

Письмо содержит завершённые за период загрузки, активные и ожидающие торренты,
прирост прогресса относительно предыдущего успешного ежедневного отчёта, количество
остановок/возобновлений/справедливых ротаций и список объектов для проверки. Первый
отчёт охватывает предыдущие 24 часа, последующие — период после последнего успешно
доставленного ежедневного отчёта. Если контейнер был выключен в 09:00, отчёт будет
отправлен после запуска в тот же день. Внеплановый отчёт не меняет границы следующего
ежедневного отчёта.

Основные пороги можно менять без пересборки:

```dotenv
TORRENT_ANALYTICS_NO_PROGRESS_AFTER=3d
TORRENT_ANALYTICS_NO_SEEDS_AFTER=3d
TORRENT_ANALYTICS_NEAR_COMPLETE_PROGRESS=0.95
TORRENT_ANALYTICS_NEAR_COMPLETE_STALLED_AFTER=1d
TORRENT_ANALYTICS_MAX_UNPRODUCTIVE_ATTEMPTS=5
TORRENT_ANALYTICS_FORCED_STALLED_AFTER=6h
TORRENT_ANALYTICS_OLD_TORRENT_AFTER=14d
TORRENT_ANALYTICS_OLD_TORRENT_PROGRESS=0.10
```

### Ручной отчёт и кнопка Homepage

Ручную отправку необходимо включить отдельно и защитить случайным токеном длиной не
менее 16 символов:

```dotenv
REPORTS_MANUAL_ENABLED=true
REPORTS_MANUAL_TOKEN=replace-with-a-long-random-secret
REPORTS_MANUAL_COOLDOWN=5m
```

После перезапуска откройте `http://nas-host:8091/reports`. При первом нажатии страница
спросит токен и сохранит его только в локальном хранилище браузера. Токен не входит в
URL и не должен попадать в Git или конфигурацию Homepage. Endpoint отправки принимает
только `POST /api/reports/send` с заголовком `Authorization: Bearer ...`; повторная
отправка ограничена cooldown.

В `services.yaml` Homepage можно добавить компактную ссылку рядом с qBittorrent:

```yaml
- Загрузки:
    - qBittorrent:
        icon: qbittorrent.png
        href: http://nas-host:8080
        description: Торрент-клиент
    - Отчёт Torrent Manager:
        icon: mdi-email-fast-outline
        href: http://nas-host:8091/reports
        description: Сформировать и отправить статистику
```

Технический статус последней доставки доступен через `GET /api/reports/status`.
Рабочие файлы отчёта и истории действий находятся в каталоге `data` и должны быть
подключены как постоянный volume, как в предоставленном `compose.yaml`.

## Статистика трафика qBittorrent

Сервис раз в минуту считывает накопительные счётчики qBittorrent и сохраняет суточное состояние в `data/traffic-state.properties`. Благодаря этому значения за текущий календарный день переживают перезапуск контейнера. Граница суток определяется переменной `TZ`.

Текущая статистика доступна по адресу:

```text
GET /api/qbittorrent/traffic
```

Ответ содержит готовые для отображения строки и исходные значения в байтах:

```json
{
  "date": "2026-08-19",
  "downloadToday": "84.2 GiB",
  "uploadToday": "6.8 GiB",
  "downloadAllTime": "12.4 TiB",
  "uploadAllTime": "1.1 TiB",
  "downloadTodayBytes": 90409091072,
  "uploadTodayBytes": 7301444403,
  "downloadAllTimeBytes": 13633944184422,
  "uploadAllTimeBytes": 1209462790553,
  "trackingSince": "2026-08-19T06:00:00Z"
}
```

В первый день суточные значения считаются с момента первого успешного опроса. После следующей полуночи они соответствуют календарным суткам. Интервал можно изменить через `TRAFFIC_STATS_POLL_INTERVAL`.

Пример отдельной карточки [Homepage](https://gethomepage.dev/widgets/services/customapi/):

```yaml
- Трафик qBittorrent:
    icon: qbittorrent.png
    description: Статистика передачи данных
    widget:
      type: customapi
      url: http://nas-host:8091/api/qbittorrent/traffic
      refreshInterval: 60000
      mappings:
        - field: downloadToday
          label: Скачано сегодня
        - field: uploadToday
          label: Отдано сегодня
        - field: downloadAllTime
          label: Скачано всего
        - field: uploadAllTime
          label: Отдано всего
```

## Сборка и тестирование

```shell
./gradlew test
./gradlew bootJar
```

В Windows используйте `gradlew.bat` вместо `./gradlew`.

## Локальный запуск

Задайте три переменные окружения `QBITTORRENT_*`, затем выполните:

```shell
./gradlew bootRun
```

## Запуск с Docker Compose

Соберите JAR-файл, скопируйте его в `APP_DIR`, проверьте `.env` и запустите сервис:

```shell
./gradlew bootJar
docker compose up -d
```

При использовании предоставленной конфигурации Compose информация о состоянии сервиса доступна по адресу `/actuator/health` на порту `8091`.

## Версионирование

Проект следует правилам семантического версионирования. Выпуски до `1.0.0` обозначают работоспособный, но развивающийся сервис: минорные версии добавляют или изменяют функциональность, а патч-версии содержат совместимые исправления.
